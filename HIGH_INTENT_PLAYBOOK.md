# High-Intent Page Production Pipeline

_Version 1.0 — distilled from the "Does He Love Me?" build (2026-09-19)._
The canonical scaffold is `questions/love-relationships/does-he-love-me.html` + the `does-he-love-me` quiz in `assets/js/quizzes.js`. Every new high-intent page adapts that scaffold.

> **⚠️ 2026-09-19 (v2): the operative production document is now `INTENT_PAGE_PROMPT.md`** (v2 master: taxonomy module, signs-in-context, 4-col at-a-glance table, verified evidence layer from `INTENT_SOURCE_BANK.md`, static quiz-description card, post-quiz spiritual bridge, choose-guide links, shared `window.mysticdoPatternResult` renderer). This playbook remains the background reference for rules and gotchas; where §3's section order differs from the prompt's §4, **the prompt wins**.

---

## 0. What this pipeline produces

A page at `/questions/<intent-cluster>/<question-slug>` with two layers:

1. **Static GEO layer** — AI-citable, JS-independent. AI crawlers don't run JS; the page must be complete and valuable without it.
2. **Interactive layer** — a quiz that personalizes the page's framework to the user's situation, then matches them to a practice.

The first build (Does He Love Me?) took a full day because the **infrastructure** was built: the engine's `customResult` hook, the CSS, ~50 icons, the test harness. Subsequent pages reuse all of that — target **2–3 hours** for the next page in the same cluster, **3–4 hours** for a new cluster.

## 1. Before you write: the 5 intake questions

Answer these FIRST — they drive everything else. Write them into the commit message or a scratch note before touching HTML.

1. **The surface query (H1).** The exact head-term users type. *Does he love me? / Will he come back? / Is he cheating?*
2. **The real questions underneath.** Which aha-moment currents genuinely apply (see §5)? Pick 3–5, not all 8. *closure / decision / pattern / anxiety / fixation.*
3. **The N behavior patterns the quiz will produce.** No score, no verdict — patterns only. Usually 5. *consistent / genuine-connection / mixed / uneven / not-enough-evidence.*
4. **The signal questions that distinguish the patterns.** 4 questions, scored −2..+2. *communication / effort / space-response / alignment.*
5. **The intent questions that drive practice matching.** 2 questions: what they want to know + what would help. These map to `/psychic/` `/tarot/` `/astrology/` `/do-what-fits` etc.

If you can't answer all 5 cleanly, the page isn't ready to build. Go back to the intake.

---

## 2. The two-layer architecture (non-negotiable)

- **Static first, interactive second.** The static layer is the AI-citation asset; the quiz personalizes it but never replaces it. If JS is off, the page is still a complete, valuable, quotable article.
- **The quiz result lives inside `#quiz` and is generated by JS.** No AI crawler will see it. So every result block (what your answers suggest / what they don't tell you / what to look at next) must echo a concept the static page already established — the result *applies* the framework, it doesn't introduce new claims.
- **Why this matters for GEO:** AI answers "does he love me" by retrieving the static page's direct-answer + framework + at-a-glance table. The quiz is the click-bridge — the reason a user who saw the citation still clicks through.

## 3. Page section template (canonical order)

Copy this order from `does-he-love-me.html`. Adapt the copy, keep the structure.

1. **Hero** — breadcrumbs, eyebrow (`<cluster> · Decision guide`), H1, lead, `Updated: <Month> <Year> · Reading time: ~N min`, hero-CTA row (primary → `#pattern-check`, secondary → `#which-practice`).
2. **Direct-answer band** (`section-sm`, `bg-elevated`) — the citation-atom container. 80–100 words. One self-contained, AI-quotable paragraph that answers the H1 honestly, including what *cannot* be answered.
3. **Key takeaways** (`article-body`, `key-takeaways`) — 4–5 bullets, each a citation atom.
4. **"Why the generic content fails"** — names what's wrong with existing listicle/checklist content for this question; sets up the framework as the alternative.
5. **At-a-glance table** (`cmp-scroll` + `cmp-table`, 3 cols: *observation / what it may tell you / what it cannot prove*) — 5–6 rows. This is the highest-value GEO asset; design it first.
6. **The N-signal framework** — numbered `<h3>`s (Consistency / Initiative / Investment / Alignment / Context for love). Each: what it is → what it suggests → what it doesn't prove. End with a `direct-answer` callout framing it as "practical, not scientific."
7. **Quiz section** (`#pattern-check`, `quiz-shell`) — eyebrow + h2 + subtitle + `<div id="quiz" data-quiz="<slug>">` + noscript fallback.
8. **"What you may actually be trying to know"** — the underneath currents, static version (see §5).
9. **"Which practice fits your question"** (`#which-practice`) — `cmp-table` (your real question / starting point / what it honestly offers) + "what no reading can do" callout + red-flags list + Do What Fits CTA.
10. **"Before you book"** — checklist cards (read guide / know format+cost / one question framed as dynamic / free first steps) + "when to wait instead" callout.
11. **FAQ** — 5–7 `<details class="faq-item">` (exact markup, see §10). Drives `FAQPage` JSON-LD.
12. **Methodology** — "How MysticDo approaches this question" — 5 bullets + link to `/methodology` + not-therapy disclaimer.
13. **Related pages** — `grid-3` of card links to existing pages only.

## 4. The citation-atom discipline

A citation atom is a self-contained, specific, qualified sentence an AI can reuse as evidence.

- **Bad:** "He might love you if he texts back." (vague, no qualification, not extractable)
- **Good:** "A single behavior rarely proves love; consistent patterns provide far more useful information than any isolated sign." (specific, qualified, quotable)

Rules:
- Each section's **first paragraph** = that section's citation atom. Lead with it.
- **Volative claims** (prices, platform policies, feature availability) → link to the guide that tracks them; **never hardcode in the page**. The page ages; the guides track freshness.
- **Honesty atoms** (what no reading can do, what the framework can't prove) are the differentiator. AI loves them because listicles won't say them. Write 3–5 per page.
- **No fabricated first-hand testing.** "We tested…" only if we did. Otherwise: "According to the platform…" / "Not independently verified."

## 5. Aha-moment integration rules

**Source:** `C:\Users\samja\Desktop\aha-moment.txt` (8 archetypes: Choice_Friction, Scarcity_Panic, Boundary_Invasion, Stagnation_Void, Identity_Crisis, Toxic_Loop, Sudden_Loss, Illusion_Fixation).

**Selection:** Pick only the 3–5 that genuinely apply to the question. For love: Sudden_Loss (closure), Toxic_Loop (cycle), Choice_Friction (decision), Scarcity_Panic (reassurance), Illusion_Fixation (fixation). Don't force-fit all 8.

**Translation rule — pop-evo → editorial MysticDo voice:**
- Source style: "Your genes evolved an extreme negativity bias… your Freeze defense strategy."
- MysticDo style: "When something ends without a full explanation, the mind tends to keep the question open — an unanswered question can quietly feel easier to carry than a finished answer."
- Strip the evolutionary-psychology determinism. Keep the *insight* (the underlying need driving the surface question). Per 总纲 §7: Barnum-style personalization as a **relevance enhancer**, never a diagnosis.

**⚠️ Standing rule (user, 2026-09-19): NO somatic / self-help remedies.**
- No salt-water hand-washing, closure candles, coin tosses, cold-water wrist splashes, scent changes, wardrobe purges, drawer-emptying, DND hours, sunlight resets, etc.
- The underneath block **reframes the question** (what it's really about) and **points to the kind of help that fits** (a reading vs a therapist vs nothing). It **never prescribes a self-help action**.
- Soften any "reflection aimed at…" / "grounding first" / "journaling" phrasing — these read as prescriptions. Reframe to: "the more useful frame is X — not Y."
- **Observation guidance IS allowed** ("watch who initiates over the next few weeks", "note privately how long gaps last"). That's decision intelligence, not a remedy. Keep it.

**Two surfaces per page:**
1. **Static section** "What you may actually be trying to know" — the currents as numbered h3s, each with "What fits:" line.
2. **Quiz underneath block** — one at most, conditional on answer combos. Same editorial voice.

## 6. Quiz design rules

**Structure (8 questions):**
- **Context** (2): relationship status + what triggered the question.
- **Pattern** (4, scored −2..+2): the signals that distinguish the patterns. Uncertain answers score `null` and count as "uncertain."
- **Intent** (2): what you most want to know + what would help most. These drive practice matching, not pattern scoring.

**`resolve(answers)` rules:**
- Transparent and defensible — document the model in the page's methodology section.
- Returns one of N pattern keys (≤5). **Never a numeric score or verdict.**
- Handle "uncertain" answers: if ≥2 uncertain AND |sum|<3 → `not-enough-evidence`.
- Edge overrides: e.g. one-sided effort + non-positive sum → `uneven` regardless.

**Result object (per pattern):**
```
path     — badge label + h2
summary  — one-line under the h2
suggest(answers) — function composing personalized sentences from the user's specific answers
dontTell — the limitation (fixed per pattern)
watchIntro + watch(answers) — observation guidance (bullets)
```

**3 fixed result blocks (always render all three):**
1. What your answers suggest
2. What they don't tell you
3. What to look at next

**Underneath:** optional, one at most. `underneath(answers, pattern)` returns `{key, label, text}` or `null`. Priority order matters (closure > cycle > decision > reassurance > meaning — pick the first that matches).

**Practice matching:** `matchPractice(answers)` returns a key into `practice{}`. **Honest, not salesy:**
- Sometimes recommends `free_first` (the framework + Daily Card) or `general` (Do What Fits) — when the user mainly wants behavior interpretation, a reading is NOT the primary answer.
- Each practice entry: `{name, fit, href, cta, secondary:{}, note}`. The `note` is the before-you-pay honesty.
- Negative pattern (e.g. `uneven`) + paid reading → extra honest warning tip ("a reading about his feelings can quietly become a more expensive way of holding the connection together").

**`customResult(ctx)`** — the engine hook. Receives `{answers, body, emailFormHTML, bindEmailForms, restart}`. Builds the result HTML string, sets `body.innerHTML`, binds email forms + retake button + PostHog captures. See the does-he-love-me `customResult` as the reference implementation.

## 8. The 12-step production workflow (per page)

1. **Intake** — answer the 5 questions (§1). Write H1, meta description, 5 patterns, 4 signal questions, 2 intent questions.
2. **Write the static page HTML** — copy `does-he-love-me.html` as scaffold, change copy, keep structure (§3). All internal links point to **existing** pages only.
3. **Add the quiz to `quizzes.js`** — copy the `does-he-love-me` object, change `id`/`questions`/`resolve`/`results`/`underneath`/`practice`/`matchPractice`/`customResult`.
4. **Add icons to `main.js` ICONS** for any new option score-values (skip if reusing existing keys).
5. **Add the page to `seo_inject.py`** both article tuples.
6. **Add a featured link** on the parent cluster `index.html`.
7. **`node --check`** both JS files.
8. **Run the quiz logic test** — adapt `scripts/test-love-quiz.mjs` to the new slug (or generalize).
9. **Run `seo_inject.py` + `build-content-index.py`**.
10. **`npm test`** — full suite (worker + email + webmcp + markdown + love-quiz).
11. **Headless render check** — adapt `_design-check/_probe_love_render.js` URL, run it.
12. **Update memory** — append to `.workbuddy/memory/<date>.md`.

## 9. Verification checklist (the green-bar standard)

A page is not done until every box is green.

- [ ] `node --check assets/js/quizzes.js` + `node --check assets/js/main.js` — both parse.
- [ ] **Quiz logic test:** exhaustive signal combos → all N patterns reachable; intent combos → all practices reachable; `customResult` never throws across the sweep; the 3 fixed blocks present in every render.
- [ ] **`npm test`:** worker (129) + email (40) + webmcp (15) + markdown + love-quiz all green. webmcp's headless-Chrome step also confirms `main.js` header/footer injection still works.
- [ ] **`seo_inject.py`:** page appears in sitemap; `Article` + `BreadcrumbList` + `FAQPage` JSON-LD present on the page; `og:type=article`.
- [ ] **`build-content-index.py`:** page in `assets/data/content-index.json`, total < 150 KB (the MCP convert cap).
- [ ] **Headless Chrome `--dump-dom`:** H1, direct-answer band, framework, practice-fit table, FAQ details all present; quiz engine rendered Q1 with progress bar + counter; header nav + footer injected; stylesheet linked.
- [ ] **Zero truly-broken internal links.** (`validate_seo.py` reports clean-URL links as "broken" — that's a pre-existing false positive, not a regression. Verify each href resolves to a real `.html` file on disk.)

## 10. Gotchas log (the traps, so you don't repeat)

1. **`seo_inject.py` two-tuple trap.** There are TWO article lists: `if rel in (...):` (ends `):`) and `is_guide_article = rel in (...)` (ends `)`). A single `replace_all` on a string ending `):` only hits the first. **Edit both, separately.** Symptom: `og:type=article` meta present but JSON-LD shows `WebPage` (not `Article`) and no `FAQPage`. Re-run seo_inject and re-check the JSON-LD after editing.

2. **`quizzes.js` seam-edit trap.** When appending a new quiz, the `old_string` must start from the PREVIOUS quiz's last result entry + all its closing braces. If you match starting at the last entry, you'll delete it and leave the previous quiz's `results` object unclosed. **Always re-read the seam after editing, run `node --check`, and re-run the logic test.** Symptom: `SyntaxError: Unexpected token '};'`.

3. **FAQ markup must be exact.** `<details class="faq-item"><summary>Q</summary><div class="faq-answer">A</div></details>`. The `seo_inject.py` regex requires literal `class="faq-item"` (no extra classes like `faq-item first`). The answer `<div class="faq-answer">` must contain no nested `<div>`s (the non-greedy capture stops at the first `</div>`).

4. **Updated-date extraction.** `seo_inject.py` parses `Updated: <Month> <Year>` → the 1st of that month. Use `Updated: September 2026` for consistency with existing pages. (The resulting `dateModified` may predate `datePublished` — a known extractor limitation, site-wide; not worth fixing per-page.)

5. **Clean URLs are canonical.** Every internal link, canonical, sitemap entry, and JSON-LD `url` is extension-less. Preview ONLY with `serve.py` — `python -m http.server` 404s clean URLs.

6. **Icon-as-score.** The engine uses `o.score` as the icon key (`getIcon(o.score)`). Each option needs a unique score value that doubles as its icon key. Add the icon to `main.js` ICONS, or it falls back to the default sparkle (acceptable but less polished for a flagship page).

7. **`customResult` `this`.** The engine calls `Q.customResult(ctx)` as a method, so `this === Q` inside. To be safe, reference `window.MYSTICDO_QUIZZES['<slug>']` directly.

8. **No somatic remedies** (user standing rule) — see §5. The underneath block reframes + points to the kind of help; it never prescribes a self-help action.

9. **`build-content-index.py` must rebuild** after ANY page copy edit — otherwise MCP/WebMCP search serves stale excerpts. The §8 workflow runs it at step 9; if you edit copy after that, re-run it.

10. **Background `serve.py`.** Start it once per session with `run_in_background=true`; reuse across all render checks. Don't start a new one per check.

11. **Shell env quirk (this machine).** The bash shim has no `cd`/`tail`/`grep`/`head`/`wc`. Use absolute paths to executables, use `findstr` (Windows) for filtering, and run Python/Node by absolute path without `cd`. `python -c` with embedded newlines is unreliable — write a `.py` file and run it instead.

12. **`validate_seo.py` clean-URL false positives.** It reports `/do-what-fits`, `/methodology`, `/guides/*` etc. as "broken" because its resolver doesn't append `.html`. These are pre-existing, not regressions. The real check is: does each href resolve to a file on disk?

## 13. What NOT to do

- Don't write a signs list. Write a framework.
- Don't give a numeric score or verdict.
- Don't prescribe somatic / self-help remedies (user standing rule).
- Don't hardcode prices or platform policies — link the tracking guide.
- Don't invent a named author (E-E-A-T decision: brand "we", functional roles).
- Don't put affiliate links as the primary CTA — practice matching first, honest caveats, then the guide.
- Don't ship without all tests green + the headless render check.
- Don't edit page copy without re-running `build-content-index.py`.
- Don't add the page to only one of the two `seo_inject.py` article tuples.
- Don't preview with `python -m http.server` — use `scripts/serve.py`.
